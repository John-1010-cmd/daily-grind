# Daily Grind（每日研磨）— 咖啡馆模拟经营游戏设计文档

> 日期：2026-09-12（v1，设计定稿，未进入开发）
> 项目目录：`daily-grind/`
> 风格母版：`daily-grind/style-reference.png`（手绘水彩咖啡馆场景，美术管线的风格锚点，与 gleamfield 同源）
> 性质：个人作品集项目，个人 + AI 辅助开发，不做商业化，中文 only

## 0. 红线与裁判标准

以下三条红线是本设计的最高约束，任何后续设计与实现决策不得违反；两条温柔化机制是红线下保留张力的唯一合法形式。

**三条红线：**

1. **无失败 / 破产 / Game Over**——不存在任何输的状态
2. **无体力系统**——不以资源条限制玩家操作量
3. **无每日强制结算与排名**——时间连续流动，无打烊、无日报、无排行榜

**两条温柔化机制（"压力全是想要，没有怕失去"）：**

- **缺货平静改点**：配方缺货时菜单置灰，顾客平静改点别的，不离开、不扣好感；代价仅是少赚那杯高价饮品的钱（行为序列见第 4 节）
- **梦想基金**（贷款）：无期限、**零息**，每笔营业收入自动存 10% 进还款罐；**允许多笔基金共存**，负债期间也可再申请，还款罐按申请先后逐笔清偿；**未清偿总额设上限**——不得超过当前进度阶段额度。阶段按**不可购买的经营指标**划分（累计完成订单数 / 累计营业收入 / 常客剧情进度，额度表为占位数值，随数值框架细化）——用基金消费不会抬高额度，杜绝阶梯式套现；达到上限须先清偿释放额度。基金是"提前一点"的助推，不是无限印钞；UI 不称"贷款"，呈现为"支持开店的前辈"与储蓄罐，装修面板顶部仅显示一个小小的还款进度条（多笔时显示合计进度）

## 1. 愿景与定位

一款以**手绘水彩治愈画风**呈现的咖啡馆模拟经营游戏。玩家经营一家街角咖啡馆：制作饮品、服务顾客、结识常客、布置店面、陪伴店猫，经营到一定规模后在异地开分店。

**核心个性组合（差异点）：**

- 治愈系画风 + 主动经营 + 挂机分店扩张
- 解压承诺具象化为三个招牌机制：**光照四时段流转**、**可互动橘猫**、**常客好感剧情**
- 与 Gleamfield 的关系：独立新项目，仅复用其美术管线与风格锚点；Gleamfield 的经济曲线、NPC 好感、商业化红线等设计可作参考

**关键决策记录：**

| 维度 | 决策 |
|---|---|
| 题材 | 单场景咖啡馆经营 + 终局 4 家分店（海边/雪夜/町屋/花房） |
| 节奏 | 主动经营为主体 + 装修收集长线 + 分店挂机 |
| 平台 | 纯 Web，桌面优先 + 触屏基础兼容；部署至 github.io |
| 技术栈 | TypeScript + Vite + PixiJS（场景）+ DOM/CSS（UI） |
| 存档 | localStorage 自动存档 + JSON 导入导出，无后端；存档带 schema 版本号与迁移入口（M0 起生效） |
| 经济 | 单货币金币；配方解锁 → 设备升级 → 装修家具 → 分店 |
| 会话密度 | 按单次 15 分钟碎片式设计：每次打开都能攒够买一件小东西 |
| 时间 | 无日循环连续流，光照四时段随游玩时长推移（三时钟模型见第 10 节） |

| 语言 | 中文 only，不做 i18n 结构 |
| 操作 | 点地移动为主（天然兼容触屏），WASD 为辅 |

## 2. 核心循环

**单次会话循环（约 15 分钟）：**

```
打开游戏（存档自动恢复，分店挂机收益结算，12h 上限）
→ 摸猫领每日小礼物（现实时间每日首次）
→ 接单/制作/上菜/收银（主动经营主体）
→ 间隙：补货 / 给常客做专属饮品 / 看一眼还款罐进度
→ 攒够一笔钱：解锁配方 / 升级设备 / 换一件家具款式
→ 关掉游戏，留下"再卖 N 杯就解锁新品"的念想
```

**长线循环：** 配方树推进 → 常客好感解锁剧情 → 装修逐槽位焕新 → 攒够分店大目标 → 解锁新风格分店 → 分店挂机反哺本店。

## 3. 玩家操作与角色

- **交互模型**：玩家控制店主角色在店内点地移动；点顾客接单、点吧台制作、点桌上菜、点家具装修、点猫摸猫——**万物皆可点，面板只为总览服务**
- **点击规则**：点击对象优先于移动——命中可交互对象直接交互；点击空地才移动；点击不可达 / 被遮挡的对象时，自动移动至其交互点再触发；移动中再次点击即改换新目标；对象交互热区略大于视觉范围（触屏防误触）。M0 即在风格母版上定义导航图与交互热区
- **动画方案**：部件切割 + 程序补间。AI 出角色全身立绘 → 抠成头/身/双臂/双腿部件 → 代码驱动补间（走路 = 身体起伏 + 四肢摆动 + 轻微倾斜，纸偶感）。不做逐帧 sprite，不上 Spine
- **寻路**：预定义导航路径点（桌椅位置固定），不做实时 A*
- **视角**：固定视角，画面永远保持锚点图的插画家构图；不做自由镜头

## 4. 顾客系统

- **随机路人**撑日常流水；**15-20 个常客**（v1 做 5 个）有名字/职业/固定偏好/好感度/迷你剧情
- 常客好感度解锁：专属故事片段 + 专属点单——**治愈感叙事的主要载体**；常客图鉴是收集长线的一部分
- 顾客被冷落：**平静离开改天再来**，不扣已有进度、不留差评；代价仅是该单的机会收入与已消耗原料（已出杯不返还，见第 5 节放弃规则）——行为与措辞均不以"惩罚"呈现
- **缺货改点行为序列**（第 0 节温柔化机制的落地行为）：生成偏好配方 → 检查库存 → 有货则确认 → 缺货则展示一次温和反馈（气泡文案）后平静改点备选配方；若全部配方均缺货，顾客平静等待片刻后改天再来（等同冷落规则，无惩罚）

## 5. 制作与配方

- **制作环节**：队列观看式为主体——选单 → 播放磨豆/萃取/拉花动画（配音效）→ 出杯。零操作，纯欣赏；设备升级缩短动画时长 / 同时做两杯
- **预留彩蛋钩子**：给常客做专属饮品时可触发一次拉花涂鸦（画成什么样对方都开心），不进日常循环，无失败
- **配方树**：3 条线（意式咖啡 / 茶饮特调 / 甜点烘焙）共 25-30 种；解锁条件 = 金币 + 熟练度前置（如卖出 30 杯拿铁解锁焦糖玛奇朵）；v1 做 8-10 种（每线 2-4 种）

### 订单状态机与任务归属

订单生命周期：`等待接单 → 已接单 → 等待制作 → 制作中 → 待上菜 → 待收银 → 完成 / 放弃`

- **状态迁移即任务**：每次状态迁移是一个原子任务，同一时间只有一个执行者；任务被领取即锁定，执行中不可抢占、不可换手（动画不打断）
- **领取规则**：店主点击 = 手动领取；店员按其指派职责自动领取对应任务；同一任务多人可领时按队列顺序先到先得；双杯设备 = 两个并行的"制作中"槽位，各自独立锁定
- **任务调度**：执行者空闲时，在其职责范围内按"**最老可领取任务优先**"（按任务创建时间）领取——持续接单不会饿死制作与上菜；**自动补货优先级最低**，不抢占订单任务，仅在无订单任务可领且库存低于阈值时触发。调度规则集中在任务调度模块，不散落在各职责实现里
- **场景切换与任务锁**：切换场景（前往分店 / 回本店）时，玩家已领取但**未开始**的任务自动释放回队列；有**执行中**的任务（制作 / 上菜 / 收银动画中）时禁止切换，入口置灰并温柔提示（"先把手头这杯做完吧"）——离店不会把任务永久锁在离场执行者身上
- **原料预占**：接单时即预占原料（从库存划扣），杜绝最后一杯被重复卖出；缺货改点机制（第 0、4 节）保证改点只落到当前有货的配方
- **放弃规则**：顾客在待收银前的任何阶段平静离开 → 订单进入放弃：未出杯的取消并全额返还预占原料；已出杯的不返还（损失一杯原料 + 一单收入，此外无惩罚）

## 6. 库存与进货

- **5-6 种原料大类**：咖啡豆 / 牛奶 / 糖浆 / 茶叶 / 烘焙原料 / 水果；每杯饮品消耗固定组合
- 原料**永不变质**；即时金币补货，无送货延迟；批量进货有折扣
- 缺货处理见第 0、4 节；后期店员可解锁**自动补货**职责，库存纳入自动化路径
- **应急原料包裹**：金币不足以补货、且梦想基金不可用或额度已用尽时，可免费领取一份最小量基础原料（呈现为"前辈的应急小包裹"）——兜底给原料不给钱：不存在无货可卖、无单可接的僵局，也无法被套现刷钱。该机制的纯逻辑随进货系统在 M1 即落地，M3 仅接入基金条件与正式文案

## 7. 经济系统

- **单货币金币**，无双货币；装饰碎片是**道具**而非货币（仅摸猫礼物产出、仅可兑换装饰，见第 11 节）
- 消耗层级：`配方解锁 → 设备升级 → 装修家具 → 分店大目标`
- 密度按单次 15 分钟碎片式设计
- **梦想基金**：见第 0 节。提供初始金币起步，允许负债，但负债语义已被温柔化机制完全收束；未清偿总额随进度阶段设上限（第 0 节），防止连续申请套现冲垮经济循环。零金币兜底由应急原料包裹承担（第 6 节）
- **经济账本**：所有金币变动经唯一账本模块原子结算。订单收入固定结算顺序：**营业额 → 店员抽成 → 梦想基金还款（10%，按申请先后）→ 玩家净入账**；自动补货等支出另起独立交易。每笔交易返回明细（收入 / 各项扣款 / 净额），HUD、存档、成就消费同一份明细——禁止各系统各自直接改金币

## 8. 店员系统

- 2-3 个有名字有立绘的**伙伴型店员**（v1 做 1 个，含其剧情线），各带一条小剧情线
- 机制上是自动化升级：雇佣后出现在店里自动干活，可指派职责（接单 / 制作 / 上菜 / 收银 / 自动补货），按订单状态机领取任务，调度规则见第 5 节"任务调度"
- **雇佣与工资**：雇佣需一次性雇佣费（小额，占位数值随数值框架细化）；入职后**持续工资制**——工资从营业收入自动抽成（每笔订单结算时经账本扣除固定比例，比例随数值框架细化）；无收入则无工资支出，余额永不为负，店员不因欠薪离开（红线 1）
- 体验上是"店里多了个伙伴"——系统包装成关系；玩家从执行者逐步变为巡视者，衔接分店挂机

## 9. 装修系统

- **固定槽位 + 款式变体**：每张桌、每盏灯、每处植物有 3-5 种可换款式（同位置同角度出图），整店可切主题色调
- 不开放网格自由摆放——构图权不交出去，保住"画风精美"卖点；管线友好（每个变体 = 一张同机位物件图）
- v1：6-8 个槽位，每槽 2-3 个变体；点击家具直接切换款式，也可从装修面板总览

## 10. 时间系统与光照

- **无日循环连续流**：店永远开着，无打烊无结算
- **三个可注入时钟**（M0 落地为时钟模块；逻辑只依赖注入值，测试用假时钟）：
  - `activePlayTime`：玩家在线游玩累计时长（页面后台挂起时暂停计时）——驱动光照四时段循环
  - `wallClock`：现实本地时间——决定进店时段与每日礼物判定
  - `offlineElapsed` = 当前 wallClock − 存档时间戳——驱动挂机结算；负值（系统时间回拨）按 0 处理，封顶 12 小时
- 光照随 activePlayTime 缓慢推移四时段：清晨冷光 → 午后暖光 → 黄昏 → 夜晚灯串亮起成为主光源
- **现实时间联动（确定做，非可选）**：每次打开游戏时，时段先对齐 wallClock（晚上打开游戏就是夜灯模式），随后随 activePlayTime 继续推移；时区变化以当前 wallClock 重新对齐，不做补偿
- 每日礼物按本地日期判定：记录上次领取日期，仅当当前本地日期晚于该日期时可领；系统时间回拨不会重复发放

## 11. 收集图鉴、成就与猫

图鉴四类：**常客 / 饮品 / 家具 / 猫咪**；成就系统作为图鉴面板的第五个页签（见本节末）。

**橘猫（招牌机制）：** 本店常驻吉祥物，第一视觉焦点。

- 随机在店里换位置换睡姿，**睡姿图本身是收集品**
- 点击摸猫：呼噜音效 + 眯眼动画
- 现实时间每日首次摸猫掉小礼物（金币或装饰碎片）
- **装饰碎片是道具而非货币**：仅摸猫礼物产出，不可购买、不可交易；凑齐一定数量仅可兑换一件装饰（家具款式变体），所需数量随数值框架细化。碎片可兑换的款式**均为金币也可购买的普通款式**——碎片只是"提前拥有"的替代支付；不存在碎片独占内容、连续签到加成或过期奖励，"错过一天完全无感"成立。产出端（每日礼物）与兑换入口在同一里程碑（M4）落地，产出先于消费

### 成就系统

- **定位**：收集长线的另一半——图鉴记录"集齐了什么"，成就记录"做到了什么"；纯荣誉 + 轻奖励，无排行榜、无限时（红线 3）
- **类别**：经营（累计售杯 / 累计收入 / 配方线进度）/ 关系（常客好感达成、剧情解锁）/ 收集（睡姿、家具变体、饮品图鉴进度）/ 分店（解锁与挂机里程碑）
- **奖励**：以金币为主，高阶段成就仅给徽章（图鉴面板"成就"页签展示）；不产出装饰碎片，碎片保持摸猫专属
- **分店前置**：分店解锁的"前置成就"（第 12 节）从本系统选取，如"三条配方线各解锁至少 1 款""5 位常客好感均达标"；具体门槛随数值框架细化
- v1 做最小集：分店前置成就 + 每类 1-2 个；类别与数量扩充留 v2

## 12. 分店系统

- 规划 4 家分店：**海边 / 雪夜 / 町屋 / 花房**，每家 = 一套新空场景底图 + 复用全部系统（美术管线的主战场）
- **分店完整可经营**：接单 / 制作 / 上菜 / 收银 / 进货 / 装修（独立槽位与主题色调）与本店无异；库存全局共享；常客与橘猫为本店专属，v1 分店只有随机路人
- 解锁靠金币大目标 + 前置成就；可随时通过分店地图"去分店看看"切换场景
- **前往分店的前提**：本店至少有 1 名雇员在岗（本店无雇员则不可去分店），且通过任务锁校验（第 5 节：执行中任务期间禁止切换，未开始任务自动释放）；玩家离开期间本店继续营业，店员按指派职责自动运转，未指派的环节停摆（顾客平静等待或离开，无额外惩罚）
- **店铺推进模型（单一规则，不允许降级）**：所有店铺由同一经营规则模块 `advanceShop(shopState, elapsed, sharedEconomy)` 推进——前台场景渲染它，后台场景（玩家在他店）只跑逻辑不渲染，渲染只是 adapter。本店在玩家离店期间由店员驱动 advanceShop 全真推进：真实订单、消耗共享库存、未指派环节停摆。不存在"另一套后台规则"。**确定性契约**：advanceShop 是纯函数——随机状态携带于 `shopState`（或显式注入）；固定 timestep 内部推进，分段调用等价（`advanceShop(s, 1000)` ≡ 10 × `advanceShop(s, 100)`）；制作完成等状态迁移时刻由经营逻辑决定，渲染动画只是表现、不是迁移的权威来源；返回新状态与事件列表，不修改传入对象
- **挂机结算（settleWorldIdle 世界级结算）**：离线 / 挂机收益由世界模块统一结算 `settleWorldIdle(worldState, now): WorldSettlement`——计算所有店铺需求；共享库存不足时按**固定优先级**分配（本店优先，分店按解锁顺序），不足部分不计收益；统一生成账本明细；按各店 `lastSettledAt` 时间戳结算并更新，**重复调用幂等**（elapsed 为 0 则零收益，不会重复发钱）。适用场景：分店挂机（玩家回本店或离线，不依赖店员驻守）与本店离线（需至少 1 名店员在岗**且职责链完整覆盖接单 / 制作 / 上菜 / 收银**，否则环节停摆、无收益——与在线离店行为一致）。速率规则：按 config 速率表累计出杯 → 逐杯划扣共享库存原料（库存永不为负）→ 金币经账本入账；设备升级与装修提升速率表数值；离线期间自动补货不生效（店员下班不采购），挂机期间金币只增不减；每店独立 **12 小时上限**——防止纯放置化，给"回来看看"一个理由
- v1 只做 1 家分店（海边）跑通"解锁-切换场景-现场经营-挂机结算"全链路，其余 3 家留 v2

## 13. UI 骨架

- **HUD 极简且永远干净**（这幅画才是主角）：左上金币 + 时段图标；右上一排图标按钮（配方 / 进货 / 装修 / 图鉴 / 分店地图 / 梦想基金 / 设置）；无底部工具栏
- 面板半透明水彩纸质感，打开时不遮挡店中央
- UI 全部用 DOM/CSS 实现，场景用 PixiJS 渲染
- 触屏基础兼容：点地移动天然兼容触屏，DOM 面板响应式，手机横屏能玩但不做专门优化（Gleamfield 触屏规范 v2 再议）

## 14. 美术资产量产管线

- **角色一致性**：先给每个角色生成设定参考图（turnaround），后续生成时作为 image reference 喂回；不靠裸 prompt 碰运气
- **场景分层**：生成空场景底图 + 物件在纯色背景单独生成 + 程序抠图合成——接受"AI 生成 + 程序合成"，不要求 AI 直出成品图
- 角色部件（头/身/双臂/双腿）在抠图阶段一并切出，供程序补间动画使用
- 管线工具：本地 `gpt-image-review` skill（gpt-image-2 出图 + k3-256k 审美评审），以 `style-reference.png` 为风格锚点；不可用时降级为 imagegen 类工具出图 + 人工评审（M2 T2.1 为正式前置门禁）
- **音频**：AI 生成 2-3 首 lo-fi 循环 BGM（v1 用 1 首）；制作音效从 Freesound 精选（磨豆/萃取/蒸汽棒/杯碟，ASMR 向，是制作动画的灵魂）
