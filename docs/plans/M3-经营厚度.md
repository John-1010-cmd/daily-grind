# M3 经营厚度 — 实施规划

> 对应设计文档：`docs/2026-09-12-daily-grind-design.md`（下称"设计文档"）
> 里程碑验收（设计文档第 16 节）：**长线目标成型**

装上全部长线系统：装修、常客 + 好感 + 图鉴、店员（含剧情线）、设备升级、梦想基金、成就最小集，并完成 v1 剩余成品美术量产。本里程碑结束，游戏从"能玩"变成"有长期目标"。

- 第 9 节：装修（固定槽位 + 款式变体）；第 4 节：常客与好感
- 第 11 节：图鉴四类 + 成就系统 + 装饰碎片定义（兑换入口在 M4）
- 第 8 节：店员（雇佣费 / 持续工资制 / 剧情线）；第 5 节：任务调度规则

## 任务拆解

### T3.1 装修系统

- 槽位数据结构：固定槽位 + 每槽款式变体（同位置同角度出图）；整店主题色调切换
- v1 内容：6-8 槽位 × 每槽 2-3 变体；点击家具直接切换 + 装修面板总览（DOM，半透明水彩纸质感，不遮挡店中央；HUD 右上"装修"按钮点亮）
- 装饰碎片兑换**不在本里程碑**：兑换入口随产出端（摸猫每日礼物）一并在 M4 落地，产出先于消费，避免空门（第 11 节）
- 完成标志：第 15 节装修条目可勾选

### T3.2 设备升级（第 5 节，消耗层级第二环）

- 升级项：缩短制作动画时长；双杯槽位 = 两个并行的"制作中"槽位，各自独立锁定（M1 已预留槽位数组接口）
- 价格与效果数值入 `src/config`；升级入口放配方面板或吧台交互（占位 UI）
- 完成标志：升级后动画时长与并行槽位真实生效；第 15 节设备升级条目可勾选

### T3.3 常客与好感

- 5 个常客：名字 / 职业 / 固定偏好 / 好感度 / 迷你剧情片段
- 好感度解锁：专属故事片段 + 专属点单；常客入图鉴
- 常客立绘走 M2 管线（turnaround → image reference）
- 完成标志：5 位常客的故事片段均可触发

### T3.4 图鉴面板

- 四页签（常客 / 饮品 / 家具 / 猫咪）+ 成就页签（HUD 右上"图鉴"按钮点亮）
- 完成标志：图鉴条目随游玩真实点亮

### T3.5 店员（1 个，含剧情线）

- 雇佣：一次性雇佣费（小额，入 config，第 8 节）+ **持续工资**（每笔订单收入经账本自动抽成，比例入 config；无收入则无支出；余额永不为负；店员不因欠薪离开——第 7、8 节）
- 职责指派：接单 / 制作 / 上菜 / 收银 / 自动补货，按 M1 状态机领取任务（领取 / 锁定机制 M1 已通用化）
- **任务调度**（第 5 节，集中在任务调度模块）：店员空闲时在其职责范围内"最老可领取任务优先"（按任务创建时间）；**自动补货不抢占订单任务**，仅在无订单任务可领且库存低于阈值时触发
- 剧情线一条（与常客剧情同等规格）
- 完成标志：指派完整职责链后，店主可纯巡视不操作；多任务并发时无环节饿死

### T3.6 梦想基金

- 申请 / **多笔共存**（负债期间也可再申请）/ 还款罐：每笔营业收入经账本自动存 10%，按申请先后逐笔清偿；**无期限、零息**（定稿）
- **总额度上限**：未清偿合计不得超过当前阶段额度；阶段按**不可购买的经营指标**划分（累计完成订单数 / 累计营业收入 / 常客剧情进度，额度表入 config）——用基金消费不会抬高额度，杜绝阶梯式套现；达到上限须先清偿释放额度（第 0 节）
- **应急原料包裹**（第 6 节）：纯逻辑 M1 已落地；本任务接入"基金额度已用尽"条件与正式文案（"前辈的应急小包裹"）
- UI 温柔化：不出现"贷款"，呈现为"支持开店的前辈"与储蓄罐；装修面板顶部小还款进度条（多笔时合计）；HUD 右上"梦想基金"按钮点亮
- 完成标志：负债全流程无任何压迫性文案；额度上限拒绝 / 释放与应急包裹触发行为正确

### T3.7 成就最小集

- 成就数据结构：id / 类别 / 条件 / 奖励（金币或徽章；不产装饰碎片）
- v1 最小集：分店前置成就（如"三条配方线各解锁至少 1 款""5 位常客好感达标"，门槛为占位数值）+ 每类 1-2 个
- 完成标志：成就页签可用；分店前置成就可被 M5 直接查询

### T3.8 v1 资产清单与量产

- 资产清单成文并按 T2.2 规范量产：**随机路人**（若干换色 / 部件变体）、常客 5 人（T3.3 立绘）、店员 1 人、**饮品图标** 8-10、**装修变体** 6-8 槽 × 2-3 款、**UI 皮肤**（面板水彩纸质感 + HUD 图标排）
- 完成标志：清单逐项入库；用户可见灰盒占位全部有成品替身（M6 验收"灰盒为零"）

### T3.9 账本与调度测试

- 单元测试：订单结算顺序（营业额 → 店员抽成 → 基金还款 → 净入账）、多笔基金按申请先后清偿、额度上限拒绝与清偿释放、基金消费不抬高额度（阶梯套现回归）、应急原料包裹触发条件（含金基金额度已用尽分支）、自动补货支出独立成交易、余额永不为负
- 任务调度：最老任务优先、补货不抢占订单任务、单店员全职责链无环节饿死
- 完成标志：Vitest 全绿并纳入 CI

## 红线自检

- 基金 UI 无"贷款"字样；零息；额度上限是防套现而非压迫（还款只从收入抽成，永不催收）；应急包裹保证无僵局（第 0、6、7 节）
- 工资永不让余额为负（红线 1）；成就无排行榜、无限时（红线 3）

## 风险与对策

- 内容量最大（5 常客剧情 + 装修变体 + 店员剧情 + 资产量产）→ 文案先行表格化，美术按 T2.2 规范并行量产
- 店员与店主抢任务 → M1 状态机领取 / 锁定规则的回归验证（调试面板 + T1.9 测试）
