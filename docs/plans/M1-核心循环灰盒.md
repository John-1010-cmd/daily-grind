# M1 核心循环灰盒 — 实施规划

> 对应设计文档：`docs/2026-09-12-daily-grind-design.md`（下称"设计文档"）
> 里程碑验收（设计文档第 16 节）：**能"玩"，玩法验收点**——M1 结束是唯一的"玩法是否成立"检查点
> 前置：M0 完成

## 目标

用占位美术与占位数值跑通单次会话循环的主体：顾客生成 → 点单 → 制作队列 → 上菜 → 收银，以及配方 / 库存 / 进货。缺货平静改点机制（第 0 节）与冷落规则（第 4 节）在本里程碑就是玩法的一部分，必须行为正确。

## 涉及设计章节

- 第 0 节：缺货平静改点；第 2 节：单次会话循环
- 第 4 节：随机路人、冷落规则、缺货改点行为序列；第 5 节：制作环节 + 订单状态机
- 第 6 节：库存与进货、应急原料包裹；第 7 节：单货币 + 经济账本；第 17 节：占位数值原则

## 任务拆解

### T1.1 订单状态机（本里程碑地基，最先做）

- 实现设计文档第 5 节状态机：`等待接单 → 已接单 → 等待制作 → 制作中 → 待上菜 → 待收银 → 完成 / 放弃`
- 规则落地：迁移即任务、领取锁定不可抢占不可换手、店主点击 = 手动领取、接单时预占原料、放弃时未出杯全额返还预占原料
- 通用接口：领取 / 锁定 / **释放**（已领取未开始的任务可释放回队列——M5 场景切换的任务锁依赖此接口）；M1 只有店主一个执行者，领取 / 锁定机制按通用接口写（M3 店员直接复用）
- 完成标志：全部状态与迁移可用 M0 调试面板实时观察

### T1.2 顾客生成器

- 随机路人（占位形象）进店 → 沿导航点落座 → 进入等待接单
- 冷落计时：超时平静离开，不扣已有进度、不留差评；已预占原料按放弃规则处理（未出杯全额返还，已出杯不返还——第 5 节）
- 完成标志：路人自动来 / 走，离开无惩罚性反馈

### T1.3 配方与点单

- 配方数据结构：id / 名称 / 原料组合 / 售价 / 解锁条件（金币 + 熟练度前置）；**熟练度累加落地**：每售出一杯对应配方计数 +1 并入存档
- 三条线占位 8-10 种（每线 2-4），占位数值集中在 `src/config`
- **缺货改点行为序列**（第 4 节）：生成偏好配方 → 检查库存 → 有货则确认 → 缺货则展示一次温和反馈（气泡占位）后改点备选配方 → 全部配方均缺货则平静等待片刻后改天再来（等同冷落规则，无惩罚）
- **配方面板占位**（DOM，HUD 右上"配方"按钮点亮）：查看已解锁 / 未解锁配方与解锁条件，条件满足时在此花金币解锁
- 完成标志：缺货时顾客有可见的"改点"行为，不离开、不扣好感，仅少赚一杯

### T1.4 库存与原料预占

- 5-6 种原料大类；接单时预占划扣，杜绝最后一杯被重复卖出
- 库存 / 进货面板占位（DOM，HUD 右上"进货"按钮点亮）
- 完成标志：并发下单不出现负库存 / 超卖

### T1.5 制作队列（占位动画）

- 选单 → 占位进度条动画 → 出杯；先单槽位，双杯槽位留给设备升级（M3）：制作槽位抽象为数组，接口预留
- 完成标志：队列先进先出，制作中不可被抢占

### T1.6 上菜与收银

- 点桌上菜（待上菜 → 待收银）
- **经济账本模块**（第 7 节）：收银入账走唯一账本 `settleOrder`；M1 先实现纯入账 + 交易明细结构（收入 / 扣款项 / 净额），店员抽成与基金还款在 M3 接入同一账本；HUD、存档、成就均消费账本明细，禁止各系统直接改金币
- 完成标志：金币流转全程可查（HUD 与存档一致，均来自账本明细）

### T1.7 进货（含应急包裹纯逻辑先行）

- 即时金币补货（经账本记支出），无送货延迟；批量折扣占位（比例入 config）
- **应急原料包裹**（第 6 节）：金币不足以补货时可免费领取最小量基础原料——M1 尚无梦想基金，先落纯逻辑与占位入口（进货面板内），M3 接入"基金额度已用尽"条件与正式文案。目的：任何时刻不存在无货可卖的死局（红线 1）
- 完成标志：补货即时反映到可点配方；花光金币 + 耗尽原料后仍可领取包裹继续经营

### T1.8 会话循环联调

- 按第 2 节单次会话循环走查。**放行条件**（占位数值，入 config）：15 分钟会话内完成 ≥ 8 单；攒够解锁第二条配方线的第一款配方；顾客平均等待 ≤ 60s；玩家无事可做时间占比 ≤ 40%
- 首次进入最小引导：点地移动 / 接单 / 制作的纯文本气泡提示（灰盒规格）
- 完成标志：完整会话无死锁、无报错，放行条件逐项达标

### T1.9 状态机与库存测试

- 单元测试：状态迁移表全遍历（合法 / 非法迁移）、重复领取竞态、原料守恒（预占 / 返还 / 消耗全程无无中生有）、放弃时机各分支（未出杯返还 / 已出杯不返还）、缺货改点序列（含全部缺货分支）、应急包裹触发条件（金币不足可领 / 充足不可领）
- 完成标志：Vitest 全绿并纳入 CI

## 不做（明确排除）

成品美术（M2）、设备升级数值（M3，仅留接口）、常客好感（M3）、店员（M3）、装修（M3）、梦想基金（M3）、猫（M2/M4）、音频（M4）、分店（M5）

## 红线自检

- 缺货改点 / 冷落离开：不扣已有进度、无差评；仅损失该单机会收入与已消耗原料（已出杯不返还，第 5 节放弃规则）——行为与措辞均不以"惩罚"呈现
- 无失败态：任何操作序列不产生 Game Over；**无死局**——花光金币 + 耗尽原料仍可领应急包裹继续经营（第 6 节）
- 无每日结算：时间连续流不打断

## 风险与对策

- 状态机边界（并发领取、放弃时机、预占返还）是最大坑 → T1.9 迁移表测试 + 调试面板全程可视化订单流转，逐条核对设计文档规则
- 占位数值手感差 → 以 T1.8 放行条件为准粗调，曲线迭代留给第 17 节

## 完成定义（DoD）

- 里程碑验收：能"玩"——单人完成 15 分钟会话循环无卡死，满足 T1.8 放行条件（单量 / 解锁目标 / 等待时长 / 空闲占比）
- 缺货改点行为序列完整可见；冷落离开不扣已有进度（仅损失机会收入与已消耗原料，与设计文档第 5 节放弃规则一致）
